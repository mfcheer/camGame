# 后台返回与声音恢复

用户反馈设备：iPhone Chrome。症状：切到其他App/锁屏再返回，词卡偶发停留、声音偶发丢失。

## 本轮修复

- `visibilitychange`、`pagehide`进入同一幂等暂停流程；`pageshow`返回时重置帧时间。重复事件不能把原来的PLAYING/CELEBRATING覆盖成PAUSED。
- 软等待在后台转为真正暂停；停止检测、清除旧指尖输入、停止词/短句/首页点读，暂停AudioContext。后台收到的延迟姿态结果直接忽略；异步预加载结束也不自动恢复声音。
- 返回保留暂停与当前进度，通过“继续游戏”的真实点击同步尝试解锁音频并重播当前词/句。兼容suspended、interrupted和closed；恢复旧卡退场时创建新卡，旧DOM延时不能删除它。
- 音频resume、fetch、decode与播放都有边界。非running或音频时钟停滞时改用独立HTML媒体播放；若浏览器拒绝自动播放或没有结束事件，显示“点一下恢复声音”，点击重建上下文并重播当前内容，不加分。词库内用小喇叭恢复。
- 旧resume/加载/播放回调按当前会话归属处理，不得启动第二段声音或覆盖新恢复结果。静音是用户选择，不当成播放故障。
- 指尖自动重听每张卡最多触发一次，防抖动反复重置计时；手动重听可继续使用。另有不随自动重听重置的总展示看门狗，避免无限停留。正常阅读时仍按真实语音结束推进。

浏览器背景参考：[MDN AudioContext状态](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/state)、[pageshow生命周期](https://developer.mozilla.org/en-US/docs/Web/API/Window/pageshow_event)。

## 已验证范围

`test/qa_v30_background_audio.mjs`覆盖16项：标准配音清单/摘要、有限等待、中断恢复、后台禁止自动恢复、时钟停滞、慢加载转媒体、自动播放拒绝、缺失ended、重建上下文、重复暂停、软等待后台化、词卡恢复、指尖抖动、手动重听、恢复异步竞态与HTML媒体停钟。

实际桌面浏览器进行了：重复visibility/pagehide/pageshow；AudioContext真正suspend/close及恢复；每次恢复检测当前语音图的非零音频信号；词卡退场中切出、连切三次、恢复按钮重建、首页点读、完整解救/宠物/告别闭环。自动化模拟生命周期与音频中断，不等同于已经在iPhone Chrome真机验收。

## iPhone Chrome家庭验收

1. 打开最新版本、保持系统音量可听，开始游戏。看到词卡/正在读单词时切去其他App，停留5–10秒再返回。
2. 应显示暂停；点“继续游戏”，同一个词重读一次，然后卡片正常收回、下一颗泡泡出现，分数不能额外增加。
3. 连续重复两三次；也试一次锁屏再返回，以及动物开场/告别正在说话时切出。
4. 若出现“点一下恢复声音”，点击后应重播当前内容。首页词库的同类恢复操作在小喇叭按钮内。
5. 留意背景音乐、破泡声、英文是否一起恢复；若仍异常，记录发生阶段、iOS/Chrome版本、锁屏还是切App，以及是否出现恢复按钮。

后续“边玩边听”版本：后台暂停语音队列，返回只恢复最近待播词，不补播积压。主动学习卡切后台会关闭并保留普通暂停，返回继续游戏；默认玩法不再有自动大词卡或指尖悬停重听。原中断兼容、有限等待、恢复按钮继续保留。
