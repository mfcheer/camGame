# 角色形象、表情与动作制作规范

本规范供以后新增或重做游戏朋友时使用。目标用户是约 3 岁半儿童，主要设备为 11 英寸 iPad。孩子应能从轮廓认出角色，从眼神和身体反应看懂“它看见我、我帮到了它、它很开心、它要去玩了”。

当前实现以代码为准；本文件说明设计意图和接入位置。完整的接入清单见 [添加游戏角色](ADD_CHARACTER.md)，已有角色的外形锚点见 [角色设计复核](CHARACTER_DESIGN_PASS.md)。

## 先写一张角色动作卡

建模前为新角色记录下列内容，避免套用其他角色的动作：

| 项目 | 要回答的问题 |
| --- | --- |
| 识别锚点 | 缩成首页头像仍能认出的轮廓、颜色和一两个关键部件是什么？ |
| 性格与运动方式 | 它是跳、跑、游、飞、滚动，还是开车？重心和速度有什么特点？ |
| 注意与回应 | 它如何看向泡泡、能量和玩家？获得能量后耳、尾、翅膀、车身或机械臂怎样回应？ |
| 表情 | 使用原有眼睛、眉、口、喙、鼻、腮等怎样表达好奇、感谢和开心？ |
| 庆祝 | 两个不同的招牌动作，以及一个仅属于它的收尾动作是什么？ |
| 告别 | 到达右侧终点时，它用哪个身体部位做一个清楚的告别动作？ |
| 声音与配色 | 哪种短音效、聚光灯和纸花颜色与它的形象一致？ |

三个动作应有不同的轮廓或节奏，例如“蹲下准备 → 跳起 → 鼓腮致谢”。同一角色的两段招牌动作可以换顺序，但收尾固定，方便幼儿建立记忆。动作设计不能依赖孩子读懂字幕。

## 游戏中的动作时序

1. **等待与观察**：受困时保持轻微呼吸和眨眼；指尖接近时看向目标，能量飞来时眼神跟随。一次泡泡命中只触发一次能量反馈，不增加额外操作。
2. **获救后的中央演出**：角色进入 `FRIEND`，约 0.8 秒走到舞台。`HappyPerformance` 从该角色的 `SIGNATURES` 选两段动作，接一段 `FINALES` 专属收尾；每段之间短暂停顿，整段通常约 5–8 秒。每段开始播放现有的角色 `happy` 音效，收尾点亮该角色配色的聚光灯与纸花。可用“和朋友说再见”跳过。
3. **告别离场**：`RescueAnimal.startEscape()` 后，前 0.65 秒为起步回应；约 0.65–3.15 秒沿跑道移动；3.15–4.10 秒转向玩家并执行 `applyFarewellPose()`；4.10–4.40 秒淡出。结算计时约 5 秒，必须等角色确实进入 `ESCAPED` 才显示结果。
4. **下一轮与中断**：暂停、切后台和返回时不让旧动作继续推进；重开或换角色后恢复默认关节、脸部、透明度和舞台状态。演出不重复计分，也不阻塞出泡及用户操作。

内部状态 `WAVING` 是历史名称，目前表示“终点告别姿势”，不意味着所有角色都挥手。新增角色按自身形体实现告别，不把车轮、履带或翅膀硬套成人手。

## 表情与动作的代码入口

| 文件与位置 | 新角色需要做的事 |
| --- | --- |
| `src/<character>Model.js` 或现有模型文件 | 创建可编辑的 Three.js 原生模型，提供命名支点；确保脸与身体层级正确。 |
| `src/rescueAnimal.js` 的 `ANIMAL_MODELS`、`modelScale` | 注册工厂、GLB 加载回退和游戏页尺寸；检查受困、能量回应、移动与重置。 |
| `src/animalExpressions.js` 的 `FACE`、`STAGE_EYES` | 调整眼睛几何尺寸/位置，选 `smile`、`slowBlink`、`wink` 或 `bright` 的演出眼神。保留角色原有眼睛与五官。 |
| `src/happyPerformance.js` 的 `ACTIONS`、`SIGNATURES`、`FINALES`、`CELEBRATION_COLORS` | 写至少两段仅该角色使用的招牌动作、一段独立收尾，以及纸花与聚光灯颜色。 |
| `src/rescueAnimal.js` 的 `applyFarewellPose()` | 为新 ID 增加终点动作；如有翅膀、须、铲斗等，还要检查 `update()` 后半段的部件动画不会覆盖它。 |
| `src/audioManager.js` 的 `playAnimalSound()` | 为 `energy`、`escape`、`happy` 检查短音效；音量和听感与现有角色一致。 |
| `scripts/build-rabbit.mjs`、`scripts/render-previews.mjs` | 将原生模型导出为本地 GLB 和透明首页预览，并在实际浏览器中检查。 |

`HappyPerformance` 的动作函数签名是 `fn(animal, t, m)`：`t` 从 0 到 1，`m` 在减少动态效果时缩小幅度。两端姿势应能回到默认状态；修改不会被 `updateFriendPose()` 每帧重置的支点时，给动作提供 `reset`。`FINALES` 必须有独立 ID、`dur` 和 `isFinale: true`。舞台的动作覆写发生在基础表情与待机姿势之后，须检查遮挡和关节方向。

外形与动作要服从角色本体：猫用尾巴、耳朵和轻扑；鸟用翅膀和喙；龙用身形、须或翅膀；车辆用车轮、车身、烟囱或铲斗。庆祝时不要再次用星星图案替换眼睛，也不要让所有角色统一跳跃、鞠躬或抬手。通用粒子可以用于收尾氛围，但主体动作和表情必须属于该角色。

## 新角色验收

- **静态辨认**：首页头像与游戏 GLB 是同一个形象；缩小看仍有识别锚点；脸部和身体没有脱节、穿模或人类化五官。
- **互动反应**：目标、能量和玩家的视线过渡自然；得到能量有清楚但不抖动的回应；暂停与减少动态效果时关节稳定。
- **完整演出**：三段动作都能从身体轮廓看出差别；眼睛仍属于原角色；两段招牌动作与一个专属收尾都可见；没有通用鞠躬、星星眼或反复的悬浮图标；完成后不留错位关节。
- **告别闭环**：角色沿自己的运动方式到右侧，执行一个清楚的告别动作，`onReachedExit` 仅触发一次；4.4 秒左右完成淡出，随后正常结算和下一轮。
- **设备与资源**：在 11 英寸 iPad 横竖屏检查全身、舞台和终点不被裁切；模拟和摄像头模式均可走通；GLB/首页图、本地音效按需加载，失败时原生模型仍可用。
- **回归**：在不覆盖用户已有 QA 结果的隔离副本运行 `npm test` 与 Pages 子路径构建；用 develop-web-game 浏览器流程截取动作中段、收尾、离场和结算画面并实际打开检查。现有专项可参考 `test/qa_v26_rhythm_demo_photo.mjs`、`test/qa_v38_character_details.mjs`、`test/qa_v41_character_farewells.mjs` 与 `test/qa_v42_character_celebrations_browser.mjs`。

如需新建或修改英语/中文语音素材，先读 [配音标准](VOICE_STANDARD.md)。不要因加角色而顺带重新生成已验收词库或短句。


## 解救后对话（2026-11-17）

用户确认的独立问答流程与自动人声例外见 [DIALOGUE_PRACTICE.md](DIALOGUE_PRACTICE.md)。新增或修改问答须先按该文档写内容卡；解救后直接提问、再出两个手势回答泡泡、自然告别，不增加聊一句／告别选择入口。对话与泡泡自动读词分开限制，共用语音通道；暂停及后台返回不重播。
