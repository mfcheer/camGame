# 资源加载顺序与抢占规则

目标是在首页尽快可操作的前提下，让用户当下选择的内容先可用。加载顺序由当前页面状态决定，不要求用户等待整库图片、音频或全部识别模型下载完。

## 首页

首屏由 HTML、CSS、主脚本、已可见的角色预览和默认角色组成。下方角色预览延迟加载。`BubbleManager` 构造时不再请求整套单词纹理；MediaPipe 主线程回退包仅在需要回退时动态导入。

页面完成加载并空闲约 750 毫秒后，`ResourceWarmup` 以低网络优先级依次预热本地识别 worker、视觉包、WASM、手部与身体模型，再预热少量单词图片。预热只下载静态文件，不请求摄像头权限，也不启动模型推理。开启省流量模式时跳过大型识别文件。切后台会暂停预热，回到首页后继续尚未完成的文件。

## 跨版本缓存

生产构建会运行 `scripts/build-cache-worker.mjs`，为发布文件计算内容指纹并生成 `service-worker.js`。首次安装只预存首页 HTML、主脚本和 CSS；识别文件、角色、词卡与音频仍由实际使用或上述空闲预热触发。开发服务器不注册 Service Worker，避免本地调试读到旧资源。

Service Worker 用内容指纹作为缓存键。发布新版本时，字节内容未变的文件保持原键并继续复用；内容变化的文件使用新键获取，旧键在新版本激活后清理。识别引擎、WASM 和主程序放在核心缓存；动物、词卡和音频放在按需缓存，空间预算为 72 MiB，超限时移除较早放入的媒体。存储不可用或写入失败时直接走网络，不阻断正常操作。浏览器仍可能清理网站存储，因此离线可用不作永久承诺。

有更新时，Service Worker 先等待。正在游戏、查看词库或营地时不会刷新页面；退出一局、关闭词库或下次打开时才激活并在首页重载。旧页面在更新切换前保持同一套版本，避免游戏中途混用素材。GitHub Pages 对页面的 HTTP 缓存仍可能让最新发布延迟数分钟出现；缓存管理不能改变服务器端尚未提供的新文件。

## 用户操作优先

打开「单词小花园」会立刻中断首页预热。词库的「全部」只先加载首屏附近图片和少量英文短读；切换某个分类时，当前分类的可见图片和英文短读先行，其他卡片随滚动再加载。主动点击卡片仍立即点读，不受后台预读队列阻塞。切换分类或关闭词库会使旧队列失效。

开始摄像头游戏或模拟游玩会立刻中断首页预热。先根据原有的分类、去重和成对规则选出本轮词池，加载本轮卡片图片、中文及英文短读，然后复用同一词池开局，不重新抽选。真实摄像头模式同时按原流程加载识别 worker、WASM 和模型，并在校准画面显示当前准备步骤。摄像头权限仍只在用户主动开始真实游戏后请求。退出时取消未完成的识别初始化，并回到首页预热状态。

## 验收

- 首次打开首页时可以立即选角色、打开词库或开始游戏；未操作时才开始低优先级预热。
- 在首页预热期间打开词库，正在传输的识别资源被中止；切分类后只优先请求该分类的可见卡片和音频。
- 开始一轮游戏时，本轮图片和短读先发起请求；校准后继续使用准备好的词池，泡泡和播报仍遵守原有规则。
- iPad 横竖屏检查词库滚动、图片出现、点读、摄像头校准、模拟游玩、退出回首页和切后台恢复。网络慢时允许图片或语音稍后到达，不应卡住游戏操作。
- 生产预览环境验证首次安装、二次打开、已访问资源的离线读取，以及版本更新时未修改模型继续复用、改过的词卡重新获取。确认游戏中更新等待，回首页后才切换。
